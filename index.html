铁路编组站驼峰纵断面与平面布置 · 多目标自动优化 · 方案一键生成
平台简介：驼峰调车是铁路编组站利用驼峰高差使车辆借助重力自动溜放、分解车列的一种高效调车方式。本平台针对驼峰峰高与纵断面（加速坡、中间坡、道岔区坡、打靶区）及减速器 / 减速顶配置进行多目标自动优化，帮助快速生成满足难行车溜放到位、易行车安全连挂约束的纵断面与平面展开方案。

多目标自动优化引擎

    

      
优化设置

      

        

          
          
        

        

          
          
        

        

          
          
        

      

      

        优化变量：峰高 H、各变坡点横向坐标 x、各变坡点高度 h（道岔位置固定，不纳入优化变量）。支持 MOPSO / NSGA-II / ALNS 三种多目标算法，适配连续纵断面变量。
      

      

        

          

          
MOPSO 粒子群

          
连续变量、收敛快、易早熟 —— 适合快速出一组 Pareto 解做初步比选。

        

        

          

          
NSGA-II 遗传算法

          
全局搜索强、多样性好、计算量大 —— 适合复杂非线性 / 多峰、追求前沿完整。

        

        

          

          
ALNS 大邻域搜索

          
局部破坏-修复、算子自适应 —— 适合已有较好初始解后精调逼近最优。

        

      

      
建议：无现成方案先点「生成初始方案」，再用 MOPSO / NSGA-II 全局搜；拿到初解后用 ALNS 精修。

能高线分析（能高法）

      
难行车·冬季（自由溜放 v推=1.4 m/s）的能高平衡：总能高 = 初始动能高 + 峰高势能；阻力能高 = 基本 + 风 + 道岔 + 曲线 四部分累计；动能高 = 总能高 − 阻力能高（对应溜放末速）

解体与溜放分配（驼峰 → 平面调车衔接）

    

      
衔接说明

      
驼峰解体只是调车作业的前半程——车辆经峰顶溜放进入各分类线（调车线）后，还需由机车在峰尾牵出线进行平面调车（取车、推进、转线、编组）。本模块把「驼峰纵断面设计」与「平面调车」通过统一的车辆状态交接接口衔接起来。

      

        
分层衔接模型（不做单一大算法）

        
① 驼峰层：峰高 / 纵断面 / 减速设备设计（本平台前 4 个标签页）；

        
② 溜放分配层：决定每辆车溜入哪条分类线（本模块）；

        
③ 平面调车层：后续取送、整理与编组（同学平台），一键导入本模块导出的 JSON 初始状态。

        
分配依据（教材 / 规范 / 知网）：同一编组去向（组号）车辆尽量溜入同一分类线，减少后续调车钩数与重复改编；禁溜车（危险货物、超限、特种车等）与禁过峰车不溜放，经禁溜线或机车送车。

      

    


    

      

        
① 待解体车列录入

        
每行一辆车：编号 车型 去向 长度 [禁]；去向＝编组去向（组号）。禁溜 / 禁过峰车不溜放、由机车送车。

        
        

          
          
        

        
车型可填 C70 / P70H / X70 / G70 / NX70 / D型 等，未写长度时按车型自动取默认车长（P70H 16.4、C70/X70/NX70 14.0、G70 12.0、D型 20.0 m）。禁溜标记：禁 / 禁溜 / 禁过峰。

      

      

        
② 分类线（调车线）配置

        
分类线按编组去向固定使用；去向数多于股道数时需合用，产生混合车流、增加二次解体。

        

          

          

        

        

          

          

        

        
股道有效长不足时，溜放车辆停放不下会形成「压车 / 堵车」，需减少溜放或借用相邻分类线（借用分类线可显著降低后续平面调车钩数）。牵出线长度与机车长度将写入导出 JSON，供平面调车平台计算取送、转线走行时间。

      

    


    

      

        
③ 分配结果与各股道占用

        
点击「解析并分配」生成分配结果。

      

      

        
④ 导出平面调车初始状态（JSON）

        
统一数据格式，供平面调车平台「一键导入」，自动生成初始的「股道—车辆—顺序」状态。

        
        

          
          
        

        
导出格式与平面调车平台（SAN 弧模型 + A* 求解器）输入完全一致：cars＝每辆车 {id, destination, length}（去向即编组组号）；tracks＝各股道 {name, capacity, initial, goal}；headshunt 牵出线长、locomotive 机车长。initial 为驼峰溜放后各分类线车辆顺序，goal 为按去向集结于股道Ⅰ的编组计划（可在其平台导入后拖拽微调）。
